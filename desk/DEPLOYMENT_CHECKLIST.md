# TIRE Desk: controlled deployment checklist

Work through these in order. Each step says whether it was **verified locally** in the 2026-10-13 release gate, or **needs checking on the live deployment**. Nothing here has been run against real Netlify, Railway or Telegram. Stop at the first step that fails and roll back as described in `RAILWAY_INTEGRATION.md` §5.

| # | Step | Status | Evidence / what to check |
|---|---|---|---|
| 1 | **Park the engine work-in-progress first.** Commit `desk/` on its own branch, without the 9 modified and 2 untracked engine files, and without `.env` or `data/`. Stage with `git add desk/`, never `git add -A`. | Needs owner action | Before committing: `git status` lists only `desk/` as staged; `git diff --cached --stat` shows no `app/`, `scripts/` or `tests/` paths |
| 2 | Delete the tombstones `desk/netlify/functions/` and `desk/server/runtime.ts` before committing | Verified locally | They contain only `export {};`. No file imports them (checked with a search plus typecheck). `netlify.toml` points functions at a directory that does not exist, so they would not deploy anyway |
| 3 | Railway: new service `tire-desk-api` from the same repo, with root `/desk` and config `/desk/railway.json` | Needs live check | `railway.json` validated locally (build `npm run build:server`, start `node dist-server/main.cjs`, health `/api/health`) |
| 4 | Railway: attach a **new** volume at `/data` to this service; set `DESK_DATA_DIR=/data/desk` | Verified locally (guard), live check needed | The production bundle refuses to start if the data directory's parent holds engine data (`persistence/`, `research_dataset/`, `reference/`, `historical_replay/`); tested: exit 1 |
| 5 | Railway variables: `SESSION_SECRET`, `APP_PASSWORD_HASH` (`npm run hash-password`), `DESK_PUBLIC_ORIGIN`, `DESK_PROXY_SECRET`; plus `UPSTOX_ANALYTICS_TOKEN` and the Telegram pair if wanted | Verified locally (refusal), live check needed | Missing or unsafe values → exit 1 with the list of problems (tested). Enter the values only in Railway's UI |
| 6 | Deploy; `GET https://<railway-domain>/api/health` → 200 with `ok: true` and no other data | Verified locally, live check needed | Test: the health payload is exactly `{ok:true}`; no secret, hash, version or directory in the body |
| 7 | Any other path on the Railway domain without the proxy key → **403** | Verified locally, live check needed | Every route in `listRoutes()` tested: direct → 403, health → 200 |
| 8 | Netlify: new site, base directory `desk`; `DESK_API_ORIGIN` and `DESK_PROXY_SECRET` with the **Functions** scope (required for Edge Functions, per Netlify docs). Variables in `netlify.toml` are not visible to edge functions, and changes need a redeploy | Needs live check | The bundle check ensures no server variable name, Railway or Telegram URL, or token-shaped string reaches `dist/` |
| 9 | Netlify accepts the build with no Functions directory (`functions = "netlify/functions-removed"`) and deploys the edge function on `/api/*` | Needs live check | Not testable without Netlify. If the build complains, delete that line; with the tombstones deleted, there are no functions to deploy |
| 10 | Set `DESK_PUBLIC_ORIGIN` on Railway to the exact final origin, then redeploy Railway. **Deploy previews, branch deploys and a custom domain are different origins:** writes from them are refused (403) unless each exact origin is listed in `DESK_ALLOWED_ORIGINS` | Verified locally, live check needed | CSRF tests plus the Deno edge probe: wrong `Origin` → 403, missing `Origin` → 403, cross-site fetch-site → 403 |
| 11 | Edge proxy on the real Netlify runtime: no session → 401; sign-in sets `__Host-desk_session` (Secure, HttpOnly, SameSite=Strict, `Path=/`, no `Domain`) | Verified locally under Deno 2.9.6, live check needed | The real `api-proxy.ts` ran under Deno with Chromium: cookie flags as listed, JS cannot read it, 401 after logout. A client-supplied `x-desk-proxy-key` is overwritten by the proxy |
| 12 | A large upload (holdings import, restore) passes through the edge proxy | Needs live check | Netlify documents a 40 s response-header limit (the proxy times out at 30 s → 504) but no request-body limit. The Desk caps bodies per route |
| 13 | Settings → **Run self-test**: record which providers work from Railway (Yahoo, NSE, Upstox, RSS) | Needs live check | The sandbox could not reach providers; no provider was verified live |
| 14 | Telegram: owner sends **one** test message from Settings | Verified locally (mocked), live check needed | Retries, 429, 401 and timeouts tested with a fake API; the token never appears in errors. No real message has been sent |
| 15 | Persistence on the real volume: add a trade, Snapshot now → Verify, download a backup, **redeploy** Railway, then confirm the trade and snapshot are still there | Verified locally, live check needed | Production bundle `kill -9` test: 3 trades survived, 0 temp files left; the browser E2E survived an upstream restart |
| 16 | Scheduler: after 10 minutes, the status page shows a healthy heartbeat and one alert-check run. Engine service watch paths exclude `/desk/**` | Verified locally, live check needed | Single-scheduler and CAS tests pass. **Known gap:** alert jobs run on weekdays 08:30–16:30 IST only, so the Muhurat session (Sun 2026-11-08, evening) gets no alerts |

**Rollback at any step:** redeploy the previous Railway deployment, or remove `DESK_API_ORIGIN` on Netlify (the proxy then returns 503). The engine service is never touched by these steps.
